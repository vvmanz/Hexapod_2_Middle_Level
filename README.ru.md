# Hexapod · средний уровень управления

**Прошивка STM32F446, связывающая приводы гексапода с ROS 2 через micro-ROS, CAN, Ethernet и систему одометрии.**

[English](README.md) | Русский

Репозиторий реализует **промежуточный уровень** трёхуровневой системы управления гексаподом. STM32F446RE принимает команды из ROS 2, передаёт задания и параметры нижним контроллерам приводов по CAN, а также обрабатывает измерения ориентации и движения от датчиков.

## Возможности

- **micro-ROS** с собственным UDP-транспортом через Ethernet-контроллер W5500 (SPI).
- **CAN-координация** трёх мостов нижнего уровня / шести каналов приводов.
- **Передача заданий углов**, коэффициентов регуляторов и дополнительных параметров.
- **Задачи FreeRTOS** для ROS-связи и обработки одометрии.
- **Оценка ориентации:** MPU6050, фильтрация сигналов и алгоритм Мэджвика.
- **Оптический поток и дальность:** приём кадров по UART DMA, оценка перемещений и скорости в плоскости.

## Архитектура

```text
Хост ROS 2 / micro-ROS agent
          │ Ethernet / UDP (W5500)
          ▼
STM32F446RE + FreeRTOS
  ├── ros_TASKS.c         команды ROS → задания / коэффициенты
  ├── CAN master          распределение команд на 3 контроллера
  └── odometry.c          IMU + оптический поток / дальность
          │
          ▼
Платы STM32F103 нижнего уровня → управление приводами
```

## Аппаратура и ПО

- **МК:** STM32F446RE, конфигурация `freeRTOS_microROS_F446RET6.ioc`.
- **Прошивка:** STM32CubeIDE, STM32 HAL, FreeRTOS и интеграция micro-ROS из проекта.
- **Связь:** W5500 по SPI, CAN, совместимый micro-ROS agent на ПК.
- **Датчики:** MPU6050 и последовательный датчик движения/дальности с протоколом, который разбирает `odometry.c`.
- **Нижний уровень** для работы с реальными двигателями.

Схемы подключения всех компонентов и отдельного полного руководства по аппаратуре в архиве нет. Проверяйте `.ioc`, сигналы и формат кадров датчика.

## Сборка и подключение

1. Импортируйте существующий проект в STM32CubeIDE.
2. Проверьте [`freeRTOS_microROS_F446RET6.ioc`](freeRTOS_microROS_F446RET6.ioc), настройки SPI, UART, CAN, I²C, GPIO.
3. Соберите `Debug` для STM32F446RE.
4. В [`Core/Src/transport_w5500.c`](Core/Src/transport_w5500.c) проверьте **статические адреса МК и ROS-агента** и адаптируйте их под локальную сеть.
5. Запустите совместимый micro-ROS agent на хосте, прошейте МК.
6. Проверьте ROS-топики и обмен по CAN **до включения силовой части**.

В [`microros_fix/`](microros_fix/) есть вспомогательный Dockerfile для пересборки статической библиотеки micro-ROS. Это обходное решение для зависимости, а не готовый установщик всего комплекса. Совместимость зависит от версии ROS/micro-ROS.

## Формат сообщений ROS

В [`Core/Src/ros_TASKS.c`](Core/Src/ros_TASKS.c) есть три обработчика массивов `std_msgs/msg/Int32MultiArray`:

| Тип сообщения | Минимальная длина | Смысл |
|---|---:|---|
| Задания углов | 6 чисел | Задание каждого канала привода |
| Коэффициенты регуляторов | 42 числа | Семь коэффициентов на канал × шесть каналов |
| Дополнительные параметры | 27 чисел | Конфигурация мостов, каналов и ограничения |

Это **специальный формат прошивки**, а не универсальный контракт ROS. Точные названия топиков и расположение полей проверяйте в исходниках перед отправкой команд.

## Структура репозитория

```text
Core/Src/main.c                  инициализация периферии и CAN
Core/Src/ros_TASKS.c             узел micro-ROS и обработчики команд
Core/Src/transport_w5500.c       транспорт Ethernet/UDP
Core/Src/odometry.c              MPU6050, ориентация, поток, одометрия
Core/Src/can_*_master.c          преобразование и передача CAN-сообщений
Core/Src/freertos.c              создание задач FreeRTOS
Core/Inc/                       заголовки, настройки, объявления W5500
Middlewares/                    исходники middleware
microros_fix/Dockerfile         вспомогательная сборка micro-ROS
*.ioc                           конфигурация STM32CubeMX
```

## Статус и ограничения

- Прошивка для работы с физическим гексаподом; **не** самостоятельный симулятор ПК.
- Сетевые адреса сейчас жёстко заданы в коде.
- В `freertos.c` создание отдельной CAN-задачи в текущей версии закомментировано. Перед эксплуатацией нужно проверить реальный порядок выполнения и тайминги CAN.
- Отдельной лицензии проекта в корне нет; для сторонних библиотек действуют их собственные лицензии.
